# 界面美化（CustomTkinter）改动清单与回滚说明

日期：2026-10-12

目的：把登录页、大厅、聊天室换成现代外观，牌桌向同一套配色靠拢。要求是**新增代码集中、可识别、可整块回滚**。

## 一、这次新增或改动的全部位置

| 位置 | 性质 | 说明 |
| --- | --- | --- |
| `client/ui_ctk.py` | 新增文件 | 本次美化的全部代码：配色表、登录页、大厅、聊天室、牌桌皮肤、ttk 深色样式 |
| `client/app.py` | 改动（3 处，均标 `[UI-CTK]`） | 顶部开关块；`ChatApp` 根窗口与 frames 选择；状态栏样式 |
| `client/app.py` | 重构（不是美化） | 牌桌控件创建抽成钩子：`_build_header/_build_seats/_build_center/_build_chat/_build_hand/_build_actions/_apply_theme/_set_button_enabled/_set_button_text`。行为与外观都不变，只是让皮肤可以覆写 |
| `client/main.py` | 改动 | 新增 `--ui ctk|classic` 参数（写入 `DDZ_UI` 环境变量） |
| `requirements.txt` | 改动 | 新增一行 `customtkinter==6.0.0` |
| `tests/test_client.py` | 改动 | 窗口冒烟测试参数化，`ctk` 与 `classic` 两种皮肤都验证 |

没有动的部分：协议、`server/`、`game/`、`client/session.py`、`client/net.py`、`client/bridge.py`、`client/cards_view.py`（牌面仍是自绘 Canvas 角标牌），以及牌桌的布局与渲染逻辑。

## 二、三种回滚方式

方式 1：启动时切回经典界面（最快，不改代码）

```powershell
.venv\Scripts\python.exe -m client --ui classic
$env:DDZ_UI = "classic"; .venv\Scripts\python.exe -m client
```

方式 2：删除新增文件（彻底回到美化前的界面）

1. 删除 `client/ui_ctk.py`；
2. 在 `client/app.py` 里删掉标记为 `[UI-CTK]` 的三处（顶部开关块、frames 选择里的 ctk 分支、状态栏样式），保留经典分支。

删掉文件后，`app.py` 的 `try/except` 会把 `UI_CTK_ENABLED` 自动置为 False，即使开关块还在也会退回经典界面；但建议把死代码一并清掉。

方式 3：连依赖一起移除

```powershell
.venv\Scripts\python.exe -m pip uninstall customtkinter
```

再把 `requirements.txt` 里的 `customtkinter==6.0.0` 一行删掉。

## 三、怎么确认回滚成功

```powershell
.venv\Scripts\python.exe -m pytest tests/test_client.py -q
.venv\Scripts\python.exe -m client --ui classic
```

第一条会同时验证两种皮肤的窗口都能建起来；第二条肉眼确认：看到浅灰底与原生按钮，就是美化前的经典界面。

## 四、后续若要把界面全部重做

1. 界面只依赖 `ClientSession` 暴露的状态与事件（`on_event(kind, data)`），换皮肤不需要碰网络层；
2. 牌桌布局与渲染在 `client/app.py::TableFrame`，皮肤通过覆写 `_build_*` 与 `_set_button_*` 钩子实现；
3. 牌面绘制在 `client/cards_view.py`，与皮肤无关，换皮肤不影响出牌交互与点击命中。
