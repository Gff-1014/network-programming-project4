# 项目四演示流程讲解文档

本文档用于从登录开始，完整演示聊天室、私聊、群聊、扫码入群、群公告、群投票、群文件、斗地主和网络故障处理。每一步都给出操作、预期结果和讲解重点。

## 一、演示前准备

### 1. 启动服务

在项目根目录打开两个 PowerShell 终端：

```powershell
# 终端 1：TCP 服务端
.venv\Scripts\python.exe -m server

# 终端 2：网页 HTTP/WebSocket 网关
.venv\Scripts\python.exe web_gateway.py
```

默认端口：

```text
TCP 服务端：127.0.0.1:9011
网页网关：0.0.0.0:8080
```

### 2. 获取网页地址

- 电脑浏览器：`http://127.0.0.1:8080/`
- 手机浏览器：`http://电脑的局域网IPv4:8080/`

当前测试机的 WLAN/局域网地址可以在网关启动输出或 `ipconfig` 中查看。手机和电脑必须处于同一局域网。

如果手机打不开页面，检查 Windows 防火墙是否放行 TCP `8080`。如果桌面客户端要从另一台电脑连接，则还需要放行 TCP `9011`，并让 TCP 服务端监听 `0.0.0.0`。

### 3. 测试账号

预置账号：

```text
wanjia1 ~ wanjia5
密码：123456
```

同一个账号只能保持一个在线连接。跨端测试请使用不同账号，例如：

```text
手机网页：wanjia1
电脑网页：wanjia2
桌面客户端：wanjia3
```

### 4. 快速自检

```powershell
# 全部测试
.venv\Scripts\python.exe -m pytest -q

# 两个网页客户端聊天/私信
.venv\Scripts\python.exe scripts\web_smoke.py

# 三个网页客户端牌桌发牌
.venv\Scripts\python.exe scripts\web_table_smoke.py

# 群公告、投票、群文件和扫码邀请
.venv\Scripts\python.exe scripts\web_group_smoke.py
```

```text

  -> 斗地主牌桌
```

对应代码主线：

```text
浏览器 WebSocket
  -> web_gateway.BrowserBridge
  -> client.session.ClientSession
  -> TCP 长度前缀 JSON 协议
  -> server.session.Session
  -> handlers / Hub / Room / Table
  -> 服务端事件推回客户端
```

相关文件：

- `web_gateway.py`：网页 HTTP/WebSocket 网关
- `client/session.py`：客户端状态和事件转换
- `server/session.py`：TCP 会话、分帧、发送队列
- `server/handlers.py`：协议消息处理器
- `server/hub.py`：账号、房间、群公告、投票和文件元数据
- `server/table.py`：牌桌与网络事件
- `web/static/app.js`：网页界面交互

## 三、登录

### 操作

1. 打开 `http://127.0.0.1:8080/`。
2. 输入账号 `wanjia1`。
3. 输入密码 `123456`。
4. 点击“登录”。

### 预期结果

- 登录页消失，进入大厅；
- 顶部显示“当前账号：wanjia1”；
- 左侧显示房间列表；
- 在线玩家显示 `wanjia1`；
- 状态变为已连接。

### 讲解重点

客户端不是直接操作数据库，而是发送 `login` 消息到 TCP 服务端。服务端校验账号、密码和唯一在线状态后返回 `welcome`，其中包含账号、token、默认房间和房间列表。

对应代码：

- `server/handlers.py::on_login`
- `server/hub.py::Hub.login`
- `client/session.py::ClientSession.login`
- `web/static/app.js::connectSocket / handleMessage`

### 可选失败演示

1. 在另一个浏览器标签页再次登录 `wanjia1`；
2. 预期提示该账号已在其他客户端登录；
3. 说明同一账号只允许一个在线连接，避免两个客户端同时操作同一身份。

## 四、大厅与在线玩家

### 操作

1. 观察大厅房间列表；
2. 点击“刷新在线玩家”；
3. 使用另一个浏览器或桌面客户端登录 `wanjia2`；
4. 回到 `wanjia1`，点击刷新。

### 预期结果

- 在线玩家中出现两个不同账号；
- 房间人数随之变化；
- 点击在线玩家 `wanjia2` 可以打开私聊。

### 讲解重点

大厅状态由服务端维护。客户端刷新时发送 `list_users`，服务端返回本房间成员和全服在线账号；网页网关只是转发这些事件。

对应代码：

- `server/handlers.py::on_list_users`
- `server/hub.py::Hub.online_accounts`
- `client/session.py::ClientSession.refresh_users`

## 五、房间聊天

### 操作

1. 点击“聊天房”；
2. 在聊天输入框输入 `网页版聊天测试`；
3. 点击“发送”；
4. 使用 `wanjia2` 进入同一聊天房；
5. 观察两个网页的消息区域。

### 预期结果

- 两个客户端都出现同一条消息；
- 大厅或其他房间的客户端不会收到这条消息；
- 房间人数和在线列表同步更新。

### 讲解重点

`Room.broadcast()` 只遍历当前房间的成员，不遍历所有在线连接，因此房间隔离由服务端保证。房间消息是可丢消息，优先保护服务端和其他客户端不被慢客户端拖住。

对应代码：

- `server/handlers.py::on_room_msg`
- `server/hub.py::Room.broadcast`
- `server/session.py::Session.send`
- `server/session.py::Session._writer_loop`

### 公共频道

房间列表中默认有三个公共频道：

```text
公共频道·综合
公共频道·技术
公共频道·闲聊
```

三个频道的管理员均为 `wanjia1`，所有已登录用户都可以进入。频道消息和普通房间消息
使用同一套持久化分页机制。

使用 `wanjia1` 登录后，房间列表旁会显示“+ 频道”，输入名称即可创建一个新的公共频道；
新频道会持久化到 SQLite，安装重启后仍然存在。

### 消息历史和分页

首次进入房间/频道时，网页显示最近 50 条消息；如果更早还有记录，会出现“加载更早消息”
按钮。私聊窗口同样提供“加载更早私信”按钮。

退出登录只会关闭当前会话，不会删除账号、群成员关系或聊天记录。重新登录后：

- 账号仍可登录；
- 已加入的群仍会显示；
- 重新进入群聊或频道可以看到历史消息；
- 私聊历史从 SQLite 恢复。

## 六、私聊

### 操作

1. 在大厅点击在线玩家 `wanjia2`；
2. 私聊面板显示“与 wanjia2 的私聊”；
3. 输入一条私聊消息并发送；
4. 在 `wanjia2` 页面查看消息；
5. 关闭私聊面板后，从“私聊会话”列表重新打开。

### 预期结果

- 发送方显示本地发送副本；
- 重新打开后能读取服务端保存的私聊历史。

私聊历史保存在 SQLite，重新登录后仍可查看。

对应代码：

- `server/handlers.py::on_private_msg`
- `server/hub.py::Hub.find_by_nickname`
- `server/hub.py::Hub.record_private`
- `client/session.py::ClientSession.open_private`

## 七、创建群聊与自定义群名

### 操作

1. 让至少两个账号登录在线；
2. 在大厅点击“建群”；
3. 输入在线账号，例如 `wanjia2`；
4. 进入新建群聊；
5. 使用群主账号点击“修改群名”；
6. 输入一个自定义名称，例如 `课程交流群`；
7. 再创建另一个群，并设置同样的群名。

### 预期结果

- 群主可以修改群名；
- 普通成员看不到“修改群名”入口；
- 两个群可以显示相同群名；
- 两个群仍拥有不同的内部房间键和独立 `group_id`。

### 讲解重点

显示群名可以重复，但内部房间键必须唯一。群文件、投票、公告和二维码都关联稳定的 `group_id`，不能只依赖显示群名。

对应代码：

- `server/hub.py::Hub.create_group`
- `server/hub.py::Hub.rename_group`
- `server/handlers.py::on_rename_group`
- `web/static/app.js::renameGroup`
- `client/app.py::RoomFrame._rename_group`
- `client/ui_ctk.py::RoomFrame._rename_group`

## 八、扫码入群

### 操作

1. 群主进入自定义群聊；
2. 点击“邀请二维码”；
3. 用手机扫描二维码；
4. 手机打开 `/join/<invite_token>` 页面；
5. 使用未加入该群的其他账号登录；
6. 登录后观察页面是否自动进入该群。

### 预期结果

- 手机扫码后打开登录页；
- 登录后提交入群申请，但不会直接进入群聊；
- 群主在“群工具”的入群申请列表中看到申请；
- 群主同意后，手机页面才进入该群；
- 群主拒绝时，申请人的页面提示申请被拒绝；
- 未入群的账号看不到该群和群工具。

### 讲解重点

二维码不是直接编码群名，而是编码带邀请 token 的 URL。服务端通过邀请 token
找到内部房间键，即使群名重复也不会申请错误的群。扫码只产生申请，群主审核通过
后才真正加入。

对应代码：

- `web_gateway.py::qr_image`
- `web_gateway.py::index` 的 `/join/{token}` 路由
- `web/static/app.js::pendingInvite`
- `server/handlers.py::on_join_invite`
- `server/hub.py::Hub.join_by_invite`

## 十、群投票

### 操作

1. 群主打开“群工具 → 群投票”；
2. 点击“发起投票”；
3. 输入标题，例如 `演示时间`；
4. 输入选项，例如 `周五,周六`；
5. 可输入截止时间，留空表示不限期；
6. 群成员点击选项投票；
7. 群主点击“结束投票”。

### 预期结果

- 投票选项显示实时票数；
- 每个账号只能投一票；
- 群主可以提前结束；
- 截止时间到达后服务端自动标记结束；
- 新成员加入后能看到当前投票和票数。

### 讲解重点

投票由服务端裁决，客户端只提交 `poll_vote`。服务端使用 `(poll_id, 账号)` 维护唯一投票，避免重复提交造成多票。

对应代码：

- `server/hub.py::GroupPoll`
- `server/hub.py::Hub.create_poll`
- `server/hub.py::Hub.vote_poll`
- `server/hub.py::Hub.close_poll`
- `server/hub.py::Hub.sweep_group_polls`
- `web/static/app.js::renderGroupFeatures`

## 十一、群文件与图片

### 操作

1. 群主或群成员打开“群工具 → 群文件”；
2. 点击“上传文件”；
3. 选择一张图片或一个普通文件；
4. 在另一个群成员页面观察群文件列表；
5. 点击图片进行预览；
6. 点击普通文件进行下载；
7. 上传者或群主点击“删除”。

### 预期结果

- 文件列表显示文件名、上传者、文件大小和 MIME 类型；
- 图片显示预览；
- 普通文件可以下载；
- 上传者可以删除自己的文件；
- 群主可以删除群内任意文件；
- 文件大小超过 20 MB 时提示失败。

### 讲解重点

文件内容不放进 64 KB 的聊天 JSON 帧，而是通过 HTTP 上传到网关的附件目录；TCP 协议只传递附件元数据。这样聊天和牌桌不会被大文件阻塞。

对应代码：

- `web_gateway.py::upload_group_file`
- `web_gateway.py::download_attachment`
- `web_gateway.py::delete_attachment`
- `server/hub.py::Hub.register_group_file`
- `server/handlers.py::on_group_file_register`
- `server/hub.py::Hub.delete_group_file`

### 操作

1. 准备三个账号；
2. 三个账号都进入 `牌桌1`；
3. 每个账号点击“准备”；
4. 三家准备完成后观察发牌；
5. 按顺序完成叫分；
6. 当前玩家选择手牌并点击“出牌”；
7. 其他玩家点击“过牌”；
8. 点击“托管”，观察服务端自动出牌；
9. 再打开一个账号进入已满牌桌，观察观战状态。

### 预期结果

- 三个座位显示三个账号；
- 每位玩家只看到自己的 17 张手牌；
- 地主获得底牌后手牌变为 20 张；

## 十五、讲解时的关键结论

1. **消息边界**：长度前缀解决 TCP 粘包和半包。
2. **并发保护**：每连接独立发送队列，慢客户端不阻塞其他人。
3. **状态归属**：账号、房间、群、投票、公告、文件元数据都由服务端统一管理。
4. **群名和群 ID**：显示群名可以重复，内部房间键和 `group_id` 唯一。
5. **大文件传输**：聊天协议传元数据，HTTP 传文件内容。
6. **扫码入群**：二维码编码邀请 token，不依赖群名。
7. **服务端裁决**：斗地主使用服务端状态机，客户端只提交动作。
8. **可验证性**：所有关键机制都有自动化测试、压测脚本或联调脚本。

## 十六、当前已知边界

- 账号、群成员、群公告、投票、群文件元数据和消息历史保存在 `data/app.db`；
- 群文件内容保存在 `data/uploads/`，文件元数据已接入 SQLite；
- 群工具界面目前主要在网页端，桌面端保留原有聊天、牌桌和群名显示；
- 网页版面向局域网 HTTP 测试，不是生产级 HTTPS 部署；
- 手机和电脑必须处于同一局域网，Windows 防火墙需要允许 `8080`。
