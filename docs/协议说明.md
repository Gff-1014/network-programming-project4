# 协议说明（M0 + M1）

## 一、分帧

TCP 之上使用**长度前缀分帧**：`4 字节大端无符号长度 + UTF-8 JSON 对象`。

| 规则 | 取值 |
| --- | --- |
| 长度字段 | 4 字节，大端（网络序） |
| 消息体 | UTF-8 编码的 JSON 对象 |
| 单帧上限 | 65536 字节（超过即回错并断开） |
| 文本长度上限 | 500 字符（`room_msg` / `private_msg`） |

一律按长度读满再解析，**不假设一次 `recv` 对应一条消息**，因此粘包与半包天然正确。
长度 0、非 UTF-8、非 JSON、非对象 → 回 `BAD_FRAME`；连续 3 次非法帧断开。

## 二、消息信封

```json
{"type": "room_msg", "request_id": "c7", "data": {"text": "大家好"}, "ts_ms": 123456}
```

* `request_id`：客户端发起请求时自带；服务端**只在对应的响应里**回填。
  广播与推送不带 `request_id`（否则会被当成别人的响应消费掉）。
* `ts_ms`：服务端单调时钟毫秒，仅由服务端填写。

## 三、客户端 → 服务端

| 类型 | data | 说明 |
| --- | --- | --- |
| `login` | `{"nickname": "..."}` | 首次登录；必须是新连接的前两个合法首帧之一 |
| `resume` | `{"token": "..."}` | 凭 token 恢复会话（断线后重连） |
| `pong` | `{}` | 回应服务端心跳 |
| `logout` | `{}` | 主动退出：立即释放昵称，不进入重连保留期 |
| `ping` | `{"echo": any}` | 客户端主动心跳，服务端回 `pong` |
| `list_rooms` | `{}` | 拉取房间列表 |
| `join_room` | `{"room": "聊天房"}` | 切换房间（自动离开原房间） |
| `leave_room` | `{}` | 回到大厅（大厅不可退出） |
| `room_msg` | `{"text": "..."}` | 房间广播 |
| `private_msg` | `{"to": "昵称", "text": "..."}` | 私信 |
| `room_ready` | `{}` | 牌桌上准备（三人齐且都准备即开局） |
| `bid` | `{"score": 0..3}` | 叫分，0 表示不叫 |
| `play` | `{"cards": ["3s","3h"]}` | 出牌，牌面用 `3s/10h/BJ/CJ` 编码 |
| `pass` | `{}` | 过牌 |
| `spectate` | `{"room": "牌桌1"}` | 观战（座位已满时） |
| `game_state` | `{}` | 拉取牌桌快照（玩家带手牌，观战者只有公开信息） |

## 四、服务端 → 客户端

| 类型 | 触发 | data |
| --- | --- | --- |
| `welcome` | 登录成功 | `conn_id`、`nickname`、`token`、`room`、`rooms`、`online`、`reconnect_grace_ms` |
| `resumed` | 重连成功 | `conn_id`、`nickname`、`token`（新）、`room`、`users`、`online` |
| `error` | 任何失败 | `code`、`message`，未知类型时附 `supported` |
| `ping` | 服务端心跳（控制类，不进队列） | `interval_ms` |
| `pong` | 收到客户端 `ping` | `echo` |
| `room_list` | 房间成员数变化 | `rooms: [{name, kind, count}]` |
| `joined` / `left` | 加入/退出结果 | `room`、`users` |
| `room_users` | 房间成员变化 | `room`、`users` |
| `user_joined` | 有人进入房间 | `nickname`、`room`、`resumed` |
| `user_reconnecting` | 有人掉线，进入重连保留期 | `nickname`、`room`、`grace_ms` |
| `user_left` | 有人离开或保留期结束 | `nickname`、`room` |
| `room_msg` | 房间内有人发言 | `room`、`from`、`text` |
| `private_msg` | 私信 | `from`、`to`、`text`（发件人副本带 `self: true`） |
| `room_msg_ack` | 房间消息已投递 | `delivered`、`room` |
| `table_state` | 牌桌公开状态变化 | 状态机、轮次、各家张数、桌面牌、倍数、剩余时间 |
| `game_start` | 发牌完成（仅本人） | `hand`（17 张）、`state`、`current` |
| `hand` | 地主拿到底牌（仅本人） | `hand`（20 张） |
| `landlord` | 定地主 | `landlord`、`bid`、`bottom`（公开）、`hand_counts` |
| `play` / `pass` / `table_cleared` | 出牌、过牌、一轮结束 | `player`、`cards`、`hand_count`、`bomb`、`multiplier` |
| `timeout` | 服务端替某人动作 | `player`、`phase`、`action` |
| `game_over` | 结算 | `winner`、`landlord_win`、`spring`、`bombs`、`multiplier`、`scores` |
| `spectating` | 观战成功 | `room`、`state` |
| `ready_ok` / `ok` | 动作成功回执 | `action`、`score`、`cards` |

## 五、错误码

| 码 | 含义 |
| --- | --- |
| `BAD_FRAME` | 分帧非法（长度 0/超限、非 UTF-8、非 JSON、非对象） |
| `TOO_MANY_BAD_FRAMES` | 连续非法帧达到上限，即将断开 |
| `UNKNOWN_TYPE` | 未知消息类型（附 `supported` 列表） |
| `NOT_LOGGED_IN` | 未登录，或首帧不是 `login` / `resume` |
| `ALREADY_LOGGED_IN` | 当前连接已经登录 |
| `HANDSHAKE_TIMEOUT` | 握手超时（默认 10 秒） |
| `INVALID_NICKNAME` | 昵称为空/超长/含空白 |
| `NICKNAME_TAKEN` | 昵称已在线，或处于重连保留期 |
| `SESSION_EXPIRED` | token 无效或重连宽限期已过 |
| `ROOM_NOT_FOUND` | 房间不存在 |
| `ALREADY_IN_ROOM` | 已在目标房间 |
| `NOT_IN_ROOM` | 不在任何房间（或试图退出大厅） |
| `USER_NOT_FOUND` | 私信目标不在线 |
| `MESSAGE_TOO_LONG` | 文本超过 500 字符 |
| `BAD_MESSAGE` | 字段缺失或类型不对 |
| `SLOW_CONSUMER` | 发送队列持续积压，连接被判定为慢客户端并断开 |
| `ROOM_FULL` | 牌桌已满（3 人 + 2 观战） |
| `NOT_SEATED` | 不在牌桌座位上 |
| `MATCH_NOT_STARTED` | 牌桌尚未开局 |
| `INVALID_BID` | 叫分不是 0/1/2/3 或低于当前最高分 |
| `INTERNAL` | 服务端处理该消息时内部异常（连接不会因此断开） |

## 六、背压：消息分三类

每个连接一个**有界**发送队列（默认 128 条、64KB 双阈值），写协程独立消费；发送路径不阻塞
其他连接。队列满时按类别处理：

| 类别 | 消息 | 队列满时 |
| --- | --- | --- |
| 可丢 | 房间广播、房间列表/成员推送 | 丢弃并计数，客户端无感 |
| 必达 | 私信、错误提示、结算 | 记录丢弃；持续积压则判定慢客户端 |
| 控制 | 心跳 | **不进队列**，直接写传输层，保证判活不被积压影响 |

慢客户端判定：`slow_consumer_window_ms` 窗口内丢弃次数达到 `slow_consumer_drop_limit`，
即清空积压、回一条 `SLOW_CONSUMER` 错误并断开（默认 10 秒内丢弃 50 条）。

## 七、心跳与判活

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| `ping_interval_ms` | 10000 | 静默超过该时长，服务端主动发 `ping` |
| `idle_timeout_ms` | 30000 | 静默超过该时长判定失效并清理 |
| `sweep_interval_ms` | 5000 | 扫描周期 |

判活依据是**收到任意合法帧**（不只是 `pong`）：客户端在持续发言就不会被误清理。

## 八、重连

登录成功时下发 `token`（32 字节随机十六进制）。连接断开后：

1. 服务端保留昵称与房间 `reconnect_grace_ms`（默认 60 秒），并广播 `user_reconnecting`；
2. 宽限期内用 `resume` 提交 token → 恢复昵称与房间，**换发新 token**（旧 token 立即失效）；
3. 宽限期结束仍未回来 → 广播 `user_left`，昵称释放。

注意：`logout`（主动退出）**不保留**预约，昵称立即释放；只有异常掉线才进入保留期。

## 九、牌桌（room.kind = "doudizhu"）

* 每桌 3 个座位，其余人按观战处理（每桌最多 2 人，超出回 `ROOM_FULL`）；
* 三人齐且都 `room_ready` → 发牌；手牌只发给本人，观战者只收公开事件；
* 叫分超时 10 秒视为不叫；出牌超时 20 秒：跟牌视为过牌、先手自动出最小单张；
* 玩家掉线保留座位并进入托管：轮到他时服务端在 `DDZ_AUTO_PLAY_DELAY_MS`（默认 1 秒）后自动决策；
  凭 token `resume` 回来即恢复座位与手牌（服务端补发 `game_state`）。

## 十、扩展方式

新增一种消息类型：在 `server/protocol.py` 的 `C2S_TYPES` 加名字，再加一个
`@register("新类型")` 处理函数。未知类型不会被当作普通消息处理，而是回 `UNKNOWN_TYPE`。
