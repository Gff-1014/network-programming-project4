# 协议说明（M0）

## 一、分帧

TCP 之上使用**长度前缀分帧**：`4 字节大端无符号长度 + UTF-8 JSON 对象`。

| 规则 | 取值 |
| --- | --- |
| 长度字段 | 4 字节，大端（网络序） |
| 消息体 | UTF-8 编码的 JSON 对象 |
| 单帧上限 | 65536 字节（超过即丢弃并断开） |
| 文本长度上限 | 500 字符（`room_msg` / `private_msg`） |

处理约定：

* 一律按长度读满再解析，**不假设一次 `recv` 对应一条消息**，因此粘包与半包天然正确；
* 长度为 0 → 回 `BAD_FRAME`；
* 长度超上限 → 回 `BAD_FRAME` 并断开（消息体未读取，字节流已错位）；
* 非 UTF-8 / 非 JSON / 非对象 → 回 `BAD_FRAME`，连续 3 次断开。

## 二、消息信封

```json
{"type": "room_msg", "request_id": "c7", "data": {"text": "大家好"}, "ts_ms": 123456}
```

* `type`：消息类型（必填）。
* `request_id`：客户端发起请求时自带；服务端在**对应的响应**里原样回填。
  广播/推送不带 `request_id`（避免与其他客户端的请求混淆）。
* `ts_ms`：服务端单调时钟毫秒，仅由服务端填写。
* `data`：消息体，始终是对象。

## 三、客户端 → 服务端（M0）

| 类型 | data | 说明 |
| --- | --- | --- |
| `login` | `{"nickname": "..."}` | 必须是连接后的第一个消息 |
| `logout` | `{}` | 主动断开 |
| `ping` | `{"echo": any}` | 心跳，服务端回 `pong` |
| `list_rooms` | `{}` | 拉取房间列表 |
| `join_room` | `{"room": "聊天房"}` | 切换房间（自动离开原房间） |
| `leave_room` | `{}` | 回到大厅（大厅不可退出） |
| `room_msg` | `{"text": "..."}` | 房间广播 |
| `private_msg` | `{"to": "昵称", "text": "..."}` | 私信 |

## 四、服务端 → 客户端（M0）

| 类型 | 触发 | data |
| --- | --- | --- |
| `welcome` | 登录成功 | `conn_id`、`nickname`、`room`、`rooms`、`online` |
| `error` | 任何失败 | `code`、`message`，未知类型时附 `supported` |
| `pong` | 收到 `ping` | `echo` |
| `room_list` | 房间成员数变化 | `rooms: [{name, kind, count}]` |
| `joined` / `left` | 加入/退出结果 | `room`、`users` |
| `room_users` | 房间成员变化 | `room`、`users` |
| `user_joined` / `user_left` | 成员上下线 | `nickname`、`room` |
| `room_msg` | 房间内有人发言 | `room`、`from`、`text` |
| `private_msg` | 私信 | `from`、`to`、`text`（发件人自己的副本带 `self: true`） |
| `room_msg_ack` | 房间消息已投递 | `delivered`（投递人数）、`room` |

## 五、错误码

| 码 | 含义 |
| --- | --- |
| `BAD_FRAME` | 分帧非法（长度 0/超限、非 UTF-8、非 JSON、非对象） |
| `TOO_MANY_BAD_FRAMES` | 连续非法帧达到上限，即将断开 |
| `UNKNOWN_TYPE` | 未知消息类型（附 `supported` 列表） |
| `NOT_LOGGED_IN` | 未登录，或首帧不是 `login` |
| `HANDSHAKE_TIMEOUT` | 握手超时（默认 10 秒） |
| `INVALID_NICKNAME` | 昵称为空/超长/含空白 |
| `NICKNAME_TAKEN` | 昵称已被在线用户占用 |
| `ROOM_NOT_FOUND` | 房间不存在 |
| `ALREADY_IN_ROOM` | 已在目标房间 |
| `NOT_IN_ROOM` | 不在任何房间（或试图退出大厅） |
| `USER_NOT_FOUND` | 私信目标不在线 |
| `MESSAGE_TOO_LONG` | 文本超过 500 字符 |
| `BAD_MESSAGE` | 字段缺失或类型不对 |
| `SLOW_CONSUMER` | 发送队列持续拥塞（M1 启用断开策略） |

## 六、扩展方式

新增一种消息类型只需两步：在 `server/protocol.py` 的 `C2S_TYPES` 里加名字，
在 `server/handlers.py` 里加一个 `@register("新类型")` 函数。
未知类型不会被当作普通消息处理，而是回 `UNKNOWN_TYPE` 并列出支持的类型。
