# 桌面客户端验证记录（Tkinter 窗口版）

日期：2026-10-12
环境：Windows，Python 3.12.14（标准库 tkinter，无第三方依赖）

## 一、结构

| 文件 | 职责 |
| --- | --- |
| `client/session.py` | 客户端会话：把协议消息变成界面可用的状态与事件，**不依赖 Tkinter**，可脱离界面测试 |
| `client/bridge.py` | 在后台线程跑 asyncio 事件循环，主线程（Tk）通过 `submit()` 发起网络动作 |
| `client/app.py` | Tkinter 界面：连接页 → 大厅 → 聊天房 / 牌桌 |
| `client/main.py`、`client/__main__.py` | 入口：`python -m client` |

线程模型：Tk 独占主线程；网络协程全部投递到后台循环执行，服务端消息通过线程安全队列
回到主线程，由 `after(50, ...)` 轮询刷新——避免了在 Tk 回调里直接跑 asyncio 的常见死锁。

## 二、界面功能

* **连接页**：服务器地址/端口/昵称；登录失败（昵称重复、握手指时等）弹出原因对话框。
* **大厅**：房间列表（含类型与人数）、在线用户、刷新、进入选中房间。
* **聊天房**：消息区、房间成员列表、私信（选中用户后发送）。
* **牌桌**：三家剩余张数、桌面牌、底牌、倍数、当前轮次与剩余秒数、对局日志；
  手牌用可点击的牌面标签（红花色标红，选中高亮）；准备/不叫/1-3 分/出牌/过牌/提示 按钮
  按状态与轮次自动启用禁用；**观战者看不到任何手牌**，也不会出现叫分与出牌按钮。
* 出牌提示：本地用规则引擎在"我的手牌 + 桌面牌"上算一手可出的组合，不依赖服务端。

### 2) 真实三窗口演示

```powershell
.venv\Scripts\python.exe -m server
.venv\Scripts\python.exe -m client --nickname demoA --auto-login --room 牌桌1 --auto-ready
.venv\Scripts\python.exe -m client --nickname demoB --auto-login --room 牌桌1 --auto-ready
.venv\Scripts\python.exe -m client --nickname demoC --auto-login --room 牌桌1 --auto-ready
```

实测（第三方客户端旁观查询）：

```text
seats: [('demoA', True), ('demoB', True), ('demoC', True)]
state: BIDDING   current: demoA
hand_counts: {'demoA': 17, 'demoB': 17, 'demoC': 17}
```

即：三个**窗口客户端**各自登录、入座、准备，服务端完成发牌并进入叫分阶段。
窗口截图见 `evidence/客户端-牌桌.png`（1016×739，采样到 216 种颜色，确认是真实渲染而非空白窗口）。

## 四、本轮修正

1. **错误提示太弱**：昵称冲突时只在状态栏写一行字，用户看不出原因（课程要求"显示原因"）。
   现在登录类错误（昵称重复/非法、握手超时、会话过期）会弹出对话框说明。
2. **观战者误触准备**：演示参数 `--auto-ready` 在观战角色上也会触发，导致弹出"不在座位"的错误。
   现在只对 `role == player` 生效，界面上观战者的准备按钮也是禁用的。
3. `ClientSession.leave_room` 之前把 `room` 置空，改为按服务端返回的 `to` 字段更新（回到大厅）。

## 五、使用提示

* 客户端退出会主动发 `logout` 并释放昵称；若直接杀进程，昵称会保留 60 秒（重连保护），
  此时用同名登录会被拒绝并提示"该昵称的会话正在重连中"。
* 演示用参数：`--nickname` 预填昵称、`--auto-login` 启动即连接、`--room` 登录后直接进房间、
  `--auto-ready` 进牌桌后自动准备（仅演示用）。
